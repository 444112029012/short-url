# ASVS 驗證等級選定：短網址服務

> 標準版本：**OWASP ASVS 5.0**（Application Security Verification Standard）。  
> 本文件為 G1 資安前置；完整 STRIDE 威脅模型屬 **G2** 交付。

---

## 1. 選定結論

| 項目 | 內容 |
|---|---|
| **選定等級** | **Level 1（驗證等級 1）** |
| **標準版本** | OWASP ASVS 5.0 |
| **適用對象** | SHORTURL MVP（練手／演示、小流量、無帳號） |
| **重評觸發** | 見 §5；觸發時須 `CR-xxx`＋使用者拍板後重選等級 |

---

## 2. 選定理由

1. **產品定位**：章程假設 A-05 與背景明示本專案為 DevSecOps **練手／演示** MVP，非正式對外營運商用服務。  
2. **威脅面縮小**：範圍外 OUT-03（無帳號／多租戶／權限）；業務不蒐集姓名、Email、電話等直接識別個資（見隱私合規 v0.1）。  
3. **流量假設**：限制 C-04 為小流量；不承諾高併發或公開商用 SLA（OUT-07）。  
4. **ASVS L1 定位**：L1 涵蓋常見攻擊的第一層防禦與可驗證基本控制，適合作為本規模服務的最低驗證基準，同時控制文件與驗證成本，利於流程示範。  
5. **專案仍加嚴處**：若干對短網址核心風險必要的控制（錯誤不洩漏、短碼熵、日誌遮罩、基本限速等）即使在 ASVS 5.0 標為 L2，本專案仍以 `SEC-xxx` 列為必須／應該（見 SEC 清單「超出 L1 基準」欄），不因選定 L1 而省略。

---

## 3. 適用範圍

下列控制領域於本專案 **適用**，並以 L1 條目為主、必要時採納個別 L2 條目寫入 SEC：

| 領域 | ASVS 5.0 章節（摘要） | 專案關聯 |
|---|---|---|
| 輸入驗證與業務邏輯 | V2 | REQ-005、REQ-006、REQ-011 |
| Web 前端／回應標頭（合理子集） | V3 | NFR-004；導向回應 |
| 安全傳輸 | V12 | 演示環境 HTTPS |
| 組態硬化（L1 項） | V13.4 等 | 不暴露版控中繼資料等 |
| 相依元件與安全編碼（L1 項） | V15 | SI-05、CI SCA／SAST |
| 日誌／錯誤（專案強制子集） | V16（多為 L2；專案仍要求） | REQ-009、隱私約束 |
| 亂數／不可預測識別子（專案強制） | V11.5（L2；專案仍要求） | REQ-006、REQ-010 |

## 4. 排除項（本輪不適用或延後）

| 排除 | 理由 |
|---|---|
| **ASVS Level 2／Level 3 全面符合** | 超出練手 MVP 與小流量假設；非對外營運 |
| **大量身份驗證／工作階段／授權控制（V6／V7／V8 主體）** | OUT-03：無帳號、無多租戶、無角色權限 |
| **OAuth／OIDC（V10）** | OUT-08 |
| **完整 STRIDE 威脅模型全文與殘餘風險接受者簽名** | 屬 **G2** 必交；本輪僅 SEC 初版並預留威脅欄（`TM-xxx` 待補） |
| **預覽頁／安全間隙頁強制實作** | OUT-10；本輪以殘餘風險書面聲明＋建議控制處理（見 SEC-002） |
| **點擊 IP／UA 明細與去重** | OUT-09；隱私文件禁止業務庫持久化 |

---

## 5. 重評條件（必須走 CR）

出現下列任一情況時，**不得**繼續僅以 L1 宣稱足夠；須開 `CR-xxx`、重評 ASVS 等級（通常至少升至 L2），並更新 SEC／威脅模型：

1. 改為**對外營運**或公開大型流量服務；  
2. **加入帳號／登入／多租戶／權限**（納入原 OUT-03 等）；  
3. **允許**將訪客 IP／User-Agent 等作為點擊明細或業務分析欄位持久化；  
4. 處理明顯提升之合規或個資範圍（超出隱私文件預設）；  
5. 使用者另行拍板要求更高驗證等級。

> 本文件對應文件手冊 `docs/00-charter/`。狀態為**已簽核 v1.0**（使用者王昱殊於 2026-10-07 簽核 D-01）。

## 1. 專案名稱與背景

| 欄位 | 內容 |
|---|---|
| 專案名稱（暫訂） | 短網址服務（Short URL Service） |
| 專案代號 | SHORTURL |
| 背景 | 本專案為 DevSecOps 專案團隊的**第一個練手專案**，用途是驗證七部門協作、G0–G6 關卡、文件手冊與資安左移流程是否跑得通。功能難度刻意壓低，以便把注意力放在流程與文件品質，而非產品複雜度。 |

---

## 2. 目標與可量測成功指標

### 2.1 專案目標
1. **流程驗證**：走完 G0→G6 一輪，產出可簽核的文件手冊與可演示的 MVP。
2. **產品 MVP**：提供可建立短碼、以短碼導向長網址、記錄點擊次數，並具備基本輸入驗證與錯誤處理的短網址服務。
3. **資安左移示範**：在設計前完成威脅建模與 SEC 清單；CI 含資安掃描門檻；上線前有殘餘風險結論。

### 2.2 成功指標（可量測）

| 編號 | 指標 | 量測方式 | 達標標準 |
|---|---|---|---|
| SI-01 | 關卡完整跑通 | `docs/gates/` 審查紀錄 | G0–G6 皆有「通過」紀錄；退回項皆關閉或經使用者接受 |
| SI-02 | 文件手冊就緒 | `docs/` 各章狀態總表 | G3 前各章為「已簽核」或「不適用（附理由）」 |
| SI-03 | MVP 核心路徑可用 | 端對端測試／手動演示 | 可建立短碼、以短碼 HTTP 導向正確長網址、點擊次數正確遞增 |
| SI-04 | 錯誤路徑可預期 | 測試案例通過 | 非法／不存在短碼、無效長網址等回傳明確錯誤（不洩漏內部細節） |
| SI-05 | 資安門檻生效 | CI 設定與 G5 資安結論 | 約定之掃描阻擋規則生效；無未關閉高風險項，或已有使用者書面接受 |

## 4. 範圍內（MVP）

以下為本專案**承諾交付**的最小可行範圍（來源：使用者定案＋企劃發想）：

| 編號 | 範圍項目 | 說明 |
|---|---|---|
| IN-01 | 建立短碼 | 提交合法長網址後，系統產生唯一短碼並回傳短網址 |
| IN-02 | 短碼導向 | 造訪短網址時，以 HTTP 重新導向至對應長網址 |
| IN-03 | 點擊次數統計 | 每次成功導向（或約定之計數時機）累加該短碼的點擊次數，並可查詢 |
| IN-04 | 基本驗證 | 長網址格式／協定限制、短碼格式約束等輸入驗證 |
| IN-05 | 錯誤處理 | 不存在短碼、無效輸入等回傳明確錯誤狀態與訊息原則（不洩漏內部資訊） |
| IN-06 | 文件與流程 | 依手冊完成 G0–G6 必交物，含資安、測試、維運相關章節 |

> 詳細功能／非功能需求編號（`REQ-`／`NFR-`／`SEC-`）於 **G1** 產出，本章程不預編完整需求表。

## 6. 限制與假設

### 6.1 限制
| 編號 | 限制 |
|---|---|
| C-01 | **時程寬鬆**：以流程驗證為優先，不設緊繃上線日；具體日曆由總協調於初步時程提出後使用者確認 |
| C-02 | **技術棧未定**：語言、框架、資料庫、託管方式等由設計部以 ADR 提議，**使用者拍板後**始定案 |
| C-03 | **單人／極小團隊操作**：開發與維運以 bot 部門協作為主，人工介入以使用者拍板與必要連線為限 |
| C-04 | **流量假設為小流量**：不承諾高併發或大型公開服務等級 |
| C-05 | **合規**：若僅儲存使用者主動提交之公開 URL 與短碼／點擊計數，個資處理範圍須於 G1 隱私合規章節明確界定；若判定不適用須書面理由 |

### 6.2 假設
| 編號 | 假設 |
|---|---|
| A-01 | 使用者同意「先完整文件手冊、G3 後才大量實作」 |
| A-02 | 七部門 bot 與總協調可持續依規範交接與送審 |
| A-03 | MVP 可採單機或單一預備／演示環境即可滿足 SI-03～SI-05 |
| A-04 | 需求細節不足處，企劃得以「企劃發想」補齊，並在來源欄標註 |
| A-05 | 短網址主要供學習／演示，不作為正式對外營運服務（除非使用者另行拍板） |

## 7. 初步風險

| 編號 | 風險 | 影響 | 可能性 | 初步因應 |
|---|---|---|---|---|
| R-01 | 範圍蔓延（自訂短碼、儀表板等提前塞入） | 高 | 中 | 嚴格維護範圍外清單；變更走 CR＋使用者拍板 |
| R-02 | 技術選型拖延導致 G2／G3 阻塞 | 中 | 中 | 設計部盡早提 ADR（至少 2 方案）；總協調設拍板期限 |
| R-03 | 惡意／不當長網址（釣魚、惡意軟體連結）被縮短散佈 | 高 | 中 | G1／G2 納入 SEC；至少基本協定／格式限制與錯誤原則；殘餘風險呈報 |
| R-04 | 文件與實作脫節（寫了不做、做了不改文件） | 高 | 中 | 審查四層檢查＋變更管理；禁止無 REQ 的功能 PR |
| R-05 | CI／環境建置耗時超過預期 | 中 | 中 | G3 關卡明確；維運與安全並行訂門檻；時程寬鬆緩衝 |
| R-06 | 點擊統計語意歧義（計數時機、重試、機器人） | 低 | 中 | G1 用可驗收標準寫死；範圍外複雜分析 |

### 6.1 v0.2 的安全檢視
**沒有新的安全疑慮**，但有兩點補充：
- **(a) gosec 遇到版本不符時會失敗，不會誤判為通過。** v0.2 §1.2 更正說，gosec 掃描時會讀本 repo 的 go.mod。研發部的證據 rd-evidence/40 顯示，如果用 Go 1.27.2 並設 `GOTOOLCHAIN=local`，會出現 `go.mod requires go >= 1.27.3` 並且 exit 1，所以檢查會失敗，不會錯誤地顯示綠燈。這屬於 R2 和 R6 已經涵蓋的風險，不算新疑慮。
- **(b) L6 出現 GO-2026-6809 以外的項目時怎麼處理。** L6 是硬條件。如果 PR 的 sca-govulncheck 出現 GO-2026-6809 以外的項目，就先判定 L6 不通過，交給安全部依 03 號 §3 的門檻裁定。裁定結果只有兩種：一是不屬於本 CR 造成，記錄後依門檻處理；二是要擋就擋。不得因為要讓本 CR 通過而放寬門檻（對應 R7）。
- 其他：§6 的 R10（合併時會經過 bypass）已經由 RR-011 和 D-17 接受，不重新評估。研發部本機用 Go 1.27.2 建置的 gosec 和 govulncheck 只影響本機，安全部同意合併後用 1.27.3 重建，不列為發現項。
